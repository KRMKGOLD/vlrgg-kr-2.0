# VLR.GG Mobile v3 — Scoreline 디자인 기록

> **Status:** 2026-11-05 채택. 토큰, 재사용 컴포넌트, 화면 12계열의 기본·상태 화면 83개, QA 화면 5개를 포함한다. 시각 계약은 루트 [DESIGN.md](../../DESIGN.md)가 소유하고, 이 문서는 작업 기록과 캔버스 구성을 남긴다. 앱 구현은 기반·공통 컴포넌트와 뉴스·경기·마이페이지·대회·시리즈·팀·선수 화면까지 적용했고 나머지 화면 배치는 후속이다.

- **편집 원본:** [`pen/vlrgg-mobile-v3.pen`](pen/vlrgg-mobile-v3.pen). Pencil에서 열어 편집하고, 앱에서 저장해야 디스크에 반영된다.
- **코드 적용:** 기반(토큰·서체·아이콘), chrome·컨트롤·피드백과 목록·상세 공통 컴포넌트(상세 상단 어두운 띠 포함), 루트 라벨 한국어, 뉴스(`10`·`11`)·경기(`20`·`21`)·마이페이지(`30`)·대회(`40`·`41`)·시리즈(`42`)·팀(`50`)·선수(`51`) 화면은 `feat/v3-design`에 적용, 나머지 화면별 배치는 후속이다. 적용 순서와 범위는 [DESIGN.md](../../DESIGN.md#11-적용-순서와-범위-밖)를 따른다.
- **제품 계약:** 정보 구조, 화면 순서, 필드, 문구, 상태 규칙은 [`docs/feature/`](../feature/README.md)를 따른다. v3는 시각 언어만 새로 정한다.

## 방향

방송 스코어 바에서 가져온 정보 디자인이다. 숫자와 팀이 먼저 읽히고 나머지는 물러난다.

1. **숫자가 먼저 읽힌다.** 점수·시각·약어는 Saira Condensed, 문장과 이름은 Noto Sans KR로 역할을 나눈다.
2. **빨강은 하나의 신호다.** LIVE, `진행 중` chip, 하단 탭 선택, 승자 표시(`승리` 라벨 포함), 즐겨찾기 ON 별, 주요 버튼, 재시도, 본문 링크에만 쓴다. 어두운 `panel` 위의 빨강 글자·아이콘(Snackbar 액션, 즐겨찾기 ON 별)은 `on-panel-accent`를 쓰고, 채운 chip(`LIVE`, `진행 중`)은 `accent` 배경에 흰 글자를 그대로 쓴다. 예정·종료를 색 chip으로 나누지 않고 텍스트로 표시한다.
3. **카드 대신 전폭 섹션을 쓴다.** 흰 섹션과 8dp 캔버스 간격으로 리듬을 만들고, 행은 구분선으로 나눈다. 카드 형태는 마이페이지 팀 타일에만 쓴다.
4. **상세는 어두운 hero로 시작한다.** 상태바·상세 헤더·hero를 한 띠로 묶는다. 로고 slot은 흰 바탕이라 어두운 로고도 보인다.
5. **없는 정보는 만들지 않는다.** 원문 문자열은 그대로 두고, 결측은 `—`, 이미지가 없으면 텍스트 placeholder를 쓴다.

### 서체

- **Noto Sans KR:** 한국어 UI, 팀·선수·대회 이름, 기사 제목과 본문. Android 시스템 한글 서체와 같은 계열이라, `.pen`에서는 시스템 서체를 대신 표현하는 용도로 쓴다.
- **Saira Condensed:** 점수, 맵 점수, 통계 수치, 팀 tag placeholder, `LIVE`, `MAP 1` 같은 약어. 좁은 폭에서 큰 숫자를 담기 위해 고른 Google Fonts 서체(OFL)다.
- 크기: display 28, title 24, section 17, body 15, body-sm 14, meta 13, label 12. 최소 글자 크기는 12다.

### 형태·간격·아이콘

- 모서리는 2dp(`radius`)다. 버튼은 10dp(`radius-button`)로 둥글게 하고, Snackbar·다이얼로그(4dp), 앱 아이콘(12dp), 선수 사진 slot(원형)도 예외로 둔다.
- 간격은 4·8·12·16·20·24·32, 화면 좌우 여백은 16dp, 섹션 사이는 8dp다. 터치 영역은 최소 48dp다.
- 아이콘은 [Google Material Symbols Outlined](https://fonts.google.com/icons) 원본을 굵기 400으로 쓴다. 패스 재작성, 라이브러리 혼용, 자체 제작 아이콘은 쓰지 않는다.
- 하단 탭은 `newspaper`, `scoreboard`, `person`, `trophy`, `info`다. 선택 상태는 ink 아이콘, 빨간 2dp 막대, 굵은 라벨로 표시한다.
- Pencil의 Material Symbols 라이브러리는 FILL 축을 지원하지 않는다. 그래서 즐겨찾기 ON 별만 Google Fonts가 배포하는 공식 `star` FILL 1 SVG를 수정 없이 컴포넌트(`C / Icon star · Material Symbols Outlined FILL 1`)로 넣었다.
- 외부 링크는 `arrow_outward`(↗), 앱 안 이동은 `chevron_right`다.

## 상태 규칙

| 상황 | 표현 | 예 |
| --- | --- | --- |
| 최초 로딩 | 실제 레이아웃과 같은 자리의 스켈레톤. hero가 있는 상세는 어두운 hero 스켈레톤, 뉴스 상세는 밝은 헤더와 본문 스켈레톤 | 뉴스·경기·대회 목록, 모든 상세 |

| 팀·선수 전체 조회 실패 | 스켈레톤 위 Error dialog: `뒤로가기`, `재시도` | `정보를 불러오지 못했습니다` |

- 상태 문구는 현재 앱 구현(`app/shared/.../ui/feature/**`)의 문구를 그대로 썼다.
- State panel은 아이콘과 문구 사이 16dp, 제목과 안내 사이 6dp, 문구와 버튼 사이 24dp다. 오류 다이얼로그는 본문과 버튼 사이 28dp이며 본문은 어절 단위로 줄을 나눈다.
- 재시도 버튼은 앱과 같이 `재시도`다. 검색 화면만 앱 구현대로 `다시 시도`다.
- 경기 상세 상태 라벨은 앱과 같이 `예정`, `완료됨`, `연기됨`, `취소됨`, `정보 없음`이다. 맵·상대 전적 섹션은 빈 목록(`맵 정보가 없습니다`)과 제공 불가(`이 경기의 맵 정보는 제공되지 않습니다`)를 구분한다.

제품 화면은 83개다. 기본 화면이 반영한 주요 계약은 다음과 같다.

- 뉴스 목록: 이미지 없는 구분선 행, 첫 기사는 큰 제목. 게시일은 날짜만 `2026년 9월 19일`이고, 시각까지(`2026년 9월 19일 오전 11:05`)는 뉴스 상세에만 쓴다.
- 경기 목록: 날짜 헤더 `9월 22일 (화)`와 `한국 시간`을 쓴다. 시간 열에는 예정이면 `오후 8:00`·`1시간 32분 후`, 종료면 `오후 6:00`·`종료`, LIVE면 `LIVE`만 표시한다. 목록에는 팀 로고가 없다.
- 경기 상세: Event 링크, 대칭 hero, `2026년 9월 21일 (월) 오후 6:00 · Bo3`, 경기 설명 원문, 맵, 상대 전적을 둔다. 예정 경기는 `2일 2시간 후 · Bo3`을 추가하고, 알림 벨은 두지 않는다(Stage 2).
- 대회 목록·상세·시리즈: 기간은 `9월 12일 ~ 10월 4일`이다. 대회 상세 경기 탭은 경기 목록과 같은 날짜 헤더로 원본 순서(날짜 오름차순)를 묶고, 문맥은 `event.series` 원문이다. 통계는 `Rounds`, `Rating`, `ACS`, `K-D`, `ADR`, `KAST` 순서이며 선수 셀만 고정한다.
- 팀·선수 상세: 팀 경기는 상태(점수 또는 `18시간 5분 후`)와 `9월 24일 오후 6:00`, 팀 뉴스는 `2026년 9월 15일`, 선수 최근 경기는 `7월 12일`로 쓴다. 스태프 행은 이동하지 않는다. 선수 요원 기록은 사용자가 Rating 내림차순을 선택한 상태의 예시이며(첫 진입은 정렬 없음, 오름차순은 `51-8`), 결측은 방향과 관계없이 마지막이다. 최근 경기는 `승리`/`패배`/`결과 미정`으로 표시한다.
- 정보: 앱 이름·버전·소개, 링크 4행(외부 `↗`, 라이선스 `>`), 테마 안내, 출처·비공식·상표 고지를 계약 원문 그대로 담는다.
- 뉴스 목록의 기사 제목·작성자와 경기 결과 탭의 대진은 2026-09 API 캡처다(결과 탭 시각은 샘플). 그 밖의 대진·점수·통계·기사 본문·팀 뉴스 제목은 레이아웃 확인용 샘플이며 실제 기록이 아니다.

  - 버튼 눌림·포커스는 별도 시안 없이 Compose 기본 표시를 쓰고, 실제로 써 보고 불편하면 조정한다([DESIGN.md 8.4](../../DESIGN.md#84-컨트롤)).

## 검증

- 채택 시(2026-11-05) Pencil 렌더로 방향 보드, 컴포넌트 보드, 87개 화면을 확인했다. 겹침, 잘림, 줄바꿈 이상을 찾아 고쳤다. LIVE 행 높이, `결과 미정` 줄바꿈, 긴 팀 이름이 겹치던 경기 행 높이가 수정 대상이었다.
- 채택 시 최상위 프레임 102개(보드 2, 줄 라벨 13, 화면 87)의 bounds를 비교해 서로 겹치는 프레임이 0개임을 확인했다.
- 위 대비 값은 WCAG 상대 휘도 공식으로 계산했다. 본문 텍스트 조합은 모두 4.5:1 이상이다.
- 채택 시 Pencil(`.pen` 2.21 형식)은 텍스트 `underline` 속성을 저장하지 않았다. 그래서 본문 링크 밑줄은 링크 텍스트를 감싼 프레임의 아래 1px 테두리로 표현했다. 구현에서는 텍스트 밑줄을 쓴다.
- 디자인·문서 작업이라 앱 코드를 변경하지 않았고 Gradle 빌드·테스트는 실행하지 않았다. 캔버스 확인은 실기기 접근성 검증을 대신하지 않는다.
- 2026-11-10 수정 후 최상위 프레임 103개(보드 2, 줄 라벨 13, 화면 88)의 bounds를 다시 비교해 겹침이 0개임을 확인했다. 이 저장부터 `.pen` 형식은 2.22다.

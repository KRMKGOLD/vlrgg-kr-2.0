## Brand

- 차분한 스포츠 정보 서비스. 따뜻한 종이색 바탕, 짙은 잉크색 텍스트, 선택과 LIVE에 집중한 빨강.
- 팀·선수·대회의 공식 이름과 기사 원제를 유지한다. UI 라벨과 날짜는 한국어로 통일한다.
- 정보의 신뢰를 장식보다 우선한다. 원본에 없는 로고·수치·경기 상태를 만들지 않는다.
- 과도한 그림자, 그라디언트, 카드 중첩, 발광 효과, 장식용 이미지, 보라색 기본 Material 배경을 피한다.

## Product goals

- 사용자가 대진, 스코어, 일정과 대회 문맥을 빠르게 읽을 수 있게 한다.
- 검색 → 상세 → 관련 정보 → 뒤로 이동 시 같은 탐색 문맥을 유지한다.
- 모든 기본·상세 화면에 일관된 헤더, 여백, 상태 표현을 제공한다.
- 정상 화면뿐 아니라 로딩·빈 결과·오류·부분 실패·즐겨찾기 복구를 설계한다.
- 성공 기준: 12개 화면 계열의 현재 제품 범위와 상태가 누락되지 않고, 360/411dp에서 정보가 겹치지 않는다.
- 제외: 계정, 동기화, 다크 모드, 고급 필터, 브래킷, 알림 설정, 경기 알림, MyPage Next Matches. 미래 단계 기능을 현재 화면에 복원하지 않는다.

## Personas and jobs

- 경기 일정·결과를 짧게 확인하는 한국어 사용자.
- 팀·선수 정보와 관련 뉴스를 이어서 확인하는 팬.
- 기기에 저장한 Team/Player 즐겨찾기에서 빠르게 상세로 이동하는 사용자.
- 작은 휴대폰, 긴 영어 고유명, 큰 글꼴, 느린 연결을 기본 사용 맥락으로 고려한다.

## Information architecture

- 하단 순서: **뉴스 → 경기 → 마이페이지 → 대회 → 정보**. 기본 진입은 마이페이지.
- 기본 탭은 제목 + 검색 + 하단 탐색을 공유한다.
- 검색과 모든 상세는 push 화면이며 하단 탐색을 두지 않는다.
- News/Event/Series/Match 상세는 뒤로 가기만 제공한다. Team/Player 상세만 즐겨찾기 별을 추가한다.
- Search는 명시적 제출, 최대 30자. 빈 값이나 기호만 있는 검색어는 제출하지 않는다. 검색어와 결과·스크롤을 복원한다.
- News/Search는 이미지 없는 구분선 목록이다. 전체 행이 상세 진입점이다.
- Match 상세: 대회 문맥 → 팀·스코어·일정 → 맵 → 상대 전적. `pastMatches`는 숨긴다.
- Event 상세: 정체성 → 경기(기본)/뉴스/통계. 탭별 데이터·상태·스크롤을 독립 보존한다.
- Team: 정체성 → 예정 경기 → 최근 경기 → 선수/스태프 → 뉴스. Player: 정체성 → 현재 팀 → 요원별 기록 → 최근 경기 최대 5개.
- MyPage는 로컬 Team/Player 즐겨찾기만 저장 순서로 표시한다. Series는 예정/완료 Event 탐색용이며 하단 탭이 아니다.

## Design principles

1. **정보 순서를 고정한다.** 경기 카드의 상태·시각, 두 팀·스코어, 대회 문맥을 같은 위치에 배치한다.
2. **목록은 평평하게 구성한다.** 뉴스·검색·정체성·경기 행을 구분선으로 나눈다. 표는 열 정렬과 배경으로 구조를 나타낸다.
3. **상태가 바뀌어도 문맥을 보존한다.** 실패한 영역에서 복구하며 다른 정상 콘텐츠를 지우지 않는다.
4. **없는 정보를 구분한다.** 실제 0, 결측값 `—`, 경기 전 스코어 없음, 데이터 로드 실패는 서로 다르다.
5. **플랫폼 여백은 한 번만 적용한다.** 시스템 안전영역과 공통 헤더의 소유자를 중복시키지 않는다.

### Typography

- 본문·고유명: `Noto Sans KR`; 스코어와 브랜드 표기: `Barlow Condensed`. 디자인용 서체이며 앱 번들 추가 결정은 별도다.
- 변수: `v2-font`, `v2-numbers`, `v2-type-{display,title,section,body,action,body-small,meta,label}`.
- 크기: Display 36, 화면 제목 28, 섹션 18, 본문 16, 액션 15, 작은 본문 14, 보조 13, 라벨 12sp. 경기 행 스코어 24, 상세 스코어 40sp.
- 본문 행간은 대체로 1.5배, 기사 본문은 1.65배. 스코어는 정렬 가능한 숫자 폭을 사용한다.
- 긴 제목과 고유명은 줄바꿈한다. 글자 크기를 줄여 맞추거나 단어 중간을 무조건 자르지 않는다.
- 큰 글꼴에서는 행·탭·하단 탐색 높이도 함께 늘린다. 130% 검증 화면에 2줄 탐색 라벨을 포함한다.

### Layout, shape, motion

- 좌우 콘텐츠 여백 20dp. 간격 4/8/12/16/20/24/32dp를 semantic 변수로 사용한다.
- 루트 헤더 64dp, 상세 헤더 56dp, 하단 탐색 콘텐츠 68dp + 플랫폼 안전영역, 도달 가능한 액션 최소 48dp.
- 컨트롤 모서리 4dp, 다이얼로그 8dp. 목록은 하단 구분선으로 나누며 개별 경기마다 둥근 상자를 만들지 않는다.
- 그림자 대신 1dp 구분선과 배경 차이를 사용한다. 상세 스코어보드만 차콜 역상으로 강조한다.
- 눌림·전환은 120–180ms. LIVE를 깜빡이지 않는다. 저동작 설정에서는 전환을 최소화한다.
- 시안은 상단 24dp 여백으로 안전영역을 표시하며 가짜 시각·배터리·통신 아이콘과 홈 표시줄을 그리지 않는다. 실제 inset은 플랫폼 값을 따른다.

### Icons

- [Google Material Symbols Outlined](https://fonts.google.com/icons) 원본을 사용한다. `.pen`의 `Material Symbols Outlined` 라이브러리를 직접 참조한다.
- 패스 재작성, 변형, 혼합 라이브러리, 커스텀 아이콘을 금지한다. 배치·색·크기만 적용한다.
- 주요 아이콘 24dp, 보조 아이콘 18–20dp, 상호작용 영역 48dp 이상. 하단: `newspaper`, `scoreboard`, `person`, `trophy`, `info`. Outlined의 기본 굵기 400을 사용한다.
- 선택은 색과 라벨로 표시한다. 선택마다 둥근 배경 타일을 반복하지 않는다.
- 긴 상세 프레임은 전체 스크롤 콘텐츠를 보여주는 캔버스 표현이다. 실제 앱 높이를 늘리거나 하단 탐색을 스크롤 끝에 붙이는 구현 지시가 아니다.

## Components

- `.pen`은 22개 재사용 컴포넌트, 39개 변수, 582개 인스턴스를 가진다. `v2-` 변수 이름은 참조 호환성을 위해 유지한다.
- Shell: 안전영역, 루트 헤더, 상세 헤더, 하단 탐색, 경기 탭, 대회 탭.
- Content: 경기 카드, 뉴스 행, 정체성 행·헤더, 섹션 제목, 스코어보드, 상대 전적 행, 통계 행.
- Controls/feedback: 기본·보조 버튼, 상태 칩, 검색창, 상태 패널, 스낵바, 스켈레톤, 오류 다이얼로그.
- 버튼·검색창은 Default/Hover/Focus/Active/Disabled/Loading/Error/Success 8개 상태를 보드에서 정의한다. 탐색·탭·행은 같은 조작 규칙을 공유하며 데이터 상태는 해당 콘텐츠 영역이 소유한다. 즐겨찾기 저장/저장됨·복구와 상태 칩도 보존한다.
- 구현에서는 기존 `VlrButton`, `VlrIconButton`, `VlrSearchField`, `StatusChip`, 공통 Match item과 Stats Table을 우선 재사용한다. 디자인 컴포넌트 수를 코드 abstraction 수로 그대로 옮기지 않는다.
- 즐겨찾기 행의 본문은 상세 이동, 별은 별도 48dp 제거 액션이다. 대상이 겹치면 안 된다.
- Match 목록의 팀 이미지는 계약상 없다. 상세 이미지 null/실패는 공식 Material Symbols의 중립적인 대체 아이콘을 표시한다.
- Team/Player에서 Event 직접 이동을 추가하지 않는다. Staff에는 Player 이동을 추가하지 않는다.
- Event/Team/Player 내 경기 카드는 Match Detail만 연다. Matches Root의 Team/Event 이동은 안정적인 ID가 있을 때만 제공한다.

## Accessibility

- WCAG 2.2 AA 취지를 따른다. 일반 텍스트 4.5:1, 큰 글자·식별에 필요한 UI 경계 3:1을 목표로 한다.
- 계산된 대비: Ink/표면 15.58:1, Muted/표면 5.66:1, Red/표면 5.36:1. 검증 스냅샷의 가시 텍스트·아이콘 조합 18개가 해당 기준을 통과했다.
- 상태는 색상 + 글자, 정렬은 화살표 + 방향 설명, 즐겨찾기는 별 + 저장 여부로 전달한다.
- 아이콘 버튼은 한국어 접근성 이름과 최소 48dp 영역을 갖는다. 반복되는 로고는 중복 낭독하지 않는다.
- 초점 순서: 뒤로 → 검색 입력 → 지우기 → 결과. 모달은 초점을 가두고 닫을 때 이전 초점을 복원한다.
- 오류/저장 결과는 읽기 순서를 방해하지 않으면서 보조기기에 알린다. 장식 스켈레톤은 낭독하지 않는다.
- 정적 디자인 검증은 TalkBack/VoiceOver, 실제 동적 글꼴, 키보드 동작 검증을 대체하지 않는다.

## Responsive behavior

- 360dp를 설계 원본으로 삼고 411dp로 확장한다. 화면 너비와 콘텐츠 열은 가변이다.
- 411dp에서 좌우 20dp 여백, 팀 이름의 가용 폭, 하단 5개 대상의 균등 분배를 유지한다.
- 통계의 정체성 열은 고정 영역으로 유지하고 지표만 가로 스크롤한다. 긴 이름은 셀 높이를 늘린다.
- 캔버스의 표는 초기 가로 위치를 보여준다. 보이지 않는 지표를 API나 구현에서 제거하지 않는다.
- Event: Player | Rounds → Rating → ACS → K-D → ADR → KAST.
- Player: Agent | Maps → Pick Rate → Rating → ACS → K/D → KAST → ADR.
- 정렬은 내림차순 → 오름차순 → 원본 순서. 숫자 기준, 결측값 마지막, 동률 원본 순서, 추가 API 요청 없음.
- 포인터 hover에 필수 기능을 숨기지 않는다. 실제 safe area와 폰트 배율은 플랫폼 값을 따른다.

## Interaction states

- **Loading:** 앱 chrome을 유지하고 실제 행의 위치에 스켈레톤을 표시한다.
- **Refresh:** 기능별 계약을 따른다. News pull-to-refresh는 목록을 즉시 초기화하고 page 1을 요청하며 진행 중 pagination을 취소하거나 늦은 응답을 무시한다. 실패는 Initial Error다. 다음 페이지 재시도와 새로고침을 혼동하지 않는다.
- **Empty:** 목록 없음, 아직 공개되지 않은 통계, 선택 필드 누락을 안전한 문구로 구분한다.
- **Initial error:** 전체 콘텐츠를 불러오지 못한 경우 재시도. Team/Player는 Retry/Back 오류 다이얼로그.
- **Pagination error:** 기존 뉴스·경기 목록 뒤에서 재시도한다. Events/Series에는 페이지네이션을 추가하지 않는다.
- **Tab error:** Event identity와 다른 탭을 보존하고 현재 탭만 재시도한다.
- **Partial:** Match의 사용 가능한 섹션을 유지한다. News의 선택 블록 누락·실패는 Populated 본문 안에서 해당 블록만 무시하며 별도 Partial 상태·전역 경고·자동 재시도를 만들지 않는다. 캔버스의 News 선택 블록 누락 프레임은 정상 본문 예시다. Team/Player/Series에도 generic Partial 화면을 만들지 않는다.
- **Favorite mutation:** 즉시 반영하고 해당 중복 액션만 제한한다. 추가 실패는 OFF, 해제 실패는 ON으로 복원 + 재시도 스낵바. 전체 화면을 막지 않는다.
- **MyPage:** Team/Player의 로딩·빈 상태·실패가 독립적이다. 제거 실패는 같은 저장 순서로 복원한다.
- **About link error:** 액션 없는 `소스 코드를 열 수 없습니다.` 스낵바. 소스 코드 행은 유지한다.
- 네트워크/파싱 실패에서 원본 오류·HTTP 코드·URL·HTML을 노출하거나 오래된 결과를 몰래 대체하지 않는다.

## Content voice

- 짧고 구체적인 한국어: “불러오지 못했어요”, “예정된 경기가 없어요”, “다시 시도”.
- 기사 원제, 팀·선수·대회 고유명, 통계 지표는 원본을 유지한다.
- 일정은 UI에서 사용자의 시간대와 locale로 변환한다. 기본 시안은 한국 시간이며 raw ISO 문자열을 함께 노출하지 않는다.
- 스코어만 보고 승패·맵 진행 상태·경기 취소를 추정하지 않는다. 실제 응답 상태를 사용한다.
- 실제 캡처에 있는 기사 제목·대진·결과를 우선 사용한다. 근거 없는 기록·기사 본문은 `—` 또는 명시적인 내용 자리표시로 바꾸며 예시 상태는 캔버스 이름·검토 문서에 구분한다. 최신 사실로 표시하지 않는다.

## Implementation constraints

- Compose Multiplatform commonMain, Navigation 3, Metro, UDF와 단일 UiState 경계를 유지한다.
- Screen은 ViewModel을 연결하고 Content에 상태·명시적 콜백을 전달한다.
- 제품 문서의 API·저장·이동 계약이 오래된 Stitch/HTML보다 우선한다.
- 기존 theme를 변경하는 별도 구현 작업에서 토큰을 이식한다. 이번 산출물은 디자인이며 앱·서버 코드는 수정하지 않았다.
- 의존성 추가, 번들 폰트 도입, 이미지 URL 추정, 새 화면 기능을 디자인만으로 승인하지 않는다.
- 구현 검증은 화면별 테스트와 실제 360/411dp, 큰 글꼴, TalkBack/VoiceOver, 정상/오류 캡처를 포함해야 한다.

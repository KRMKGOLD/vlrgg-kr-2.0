# 개인정보처리방침

Cotton(이하 "개발자")은 VLR.GG Mobile 앱(이하 "앱")을 이용하는 분의 개인정보를 「개인정보 보호법」에 따라 처리하고, 관련 사항을 다음과 같이 알립니다.

앱은 개인이 만든 비공식 앱입니다. VLR.GG 및 Riot Games와 제휴하거나 그 승인을 받지 않았으며, 앱에 표시하는 경기·팀·선수 정보는 VLR.GG의 공개 웹페이지에서 가져옵니다.

## 1. 처리하는 개인정보 항목과 처리 목적

앱에는 회원가입·로그인 기능이 없으며, 이름·연락처·이메일 같은 정보를 입력받지 않습니다. 개발자가 처리하는 정보는 아래와 같습니다.

| 구분 | 항목 | 수집 방법 | 처리 목적 |
| --- | --- | --- | --- |
| 오류 보고 | 비정상 종료 시점의 오류 기록(stack trace), Android 앱 응답 없음(ANR) 기록, Crashlytics 설치 식별자(Installation UUID), Firebase 설치 식별자(Firebase installation ID), 앱 식별자·버전, 운영체제 이름·버전과 루팅·탈옥 여부, 기기 제조사·모델명·CPU 구조·메모리(RAM)·저장공간 용량, 오류 발생 당시의 기기 상태(배터리 상태, 화면 방향, 메모리·저장공간 사용량 등) | 정식(Release) 버전에서 앱이 비정상 종료되거나 응답하지 않을 때 Firebase Crashlytics가 자동 생성·전송 | 오류 원인 파악과 수정, 영향받는 사용자 수 파악 |
| 앱 사용 세션 측정 | 세션 식별자, 첫 세션 식별자와 세션 순번, 세션 시작 시각, 앱 식별자(패키지 이름·번들 ID)·버전, 운영체제 이름·버전, 기기 모델명, Firebase 설치 식별자, SDK 버전 등 Firebase SDK가 세션 측정을 위해 수집하는 기기·앱 상태 | 정식 버전에서 오류가 없더라도 앱을 실행하거나 일정 시간이 지난 뒤 다시 화면 앞으로 가져올 때 Firebase Sessions(Crashlytics에 함께 포함되는 구성 요소)가 자동 생성·전송 | 오류 없이 사용된 세션·사용자 비율 같은 앱 안정성 지표 산출, 오류 보고와 해당 세션의 연결 |
| 조회 서버 접속 기록 | 요청 시각, 요청 주소(조회한 팀·선수·경기의 식별 번호와 검색어 포함), 접속한 기기의 IP 주소, User-Agent(앱·운영체제 정보 문자열), 요청 방식·프로토콜, 요청·응답 크기, 응답 상태, 처리 시간 | 앱이 경기·팀·선수·뉴스·검색 정보를 조회할 때 Google Cloud Run이 요청 로그를 자동 생성 | 서비스 제공, 장애 대응 |

오류 보고와 앱 사용 세션 측정의 세부 항목은 운영체제(Android·iOS)와 Firebase SDK 버전에 따라 일부만 수집될 수 있습니다.

조회 서버 접속 기록은 개발자가 만든 서버 프로그램이 아니라 Google Cloud Run이 요청마다 자동으로 남기는 요청 로그입니다.

개발자가 만든 서버 프로그램은 요청에서 나온 IP 주소, User-Agent, 검색어를 따로 저장하거나 서버 로그에 쓰지 않습니다. 서버 프로그램이 남기는 운영 기록은 요청 건수·응답 상태·처리 시간 같은 집계값과, 오류가 났을 때의 오류 종류·서버 코드 위치·요청 추적 번호입니다. 요청 추적 번호로 같은 요청의 접속 기록을 찾을 수 있으므로, 이 운영 기록도 접속 기록과 같은 곳에 같은 기간 보관합니다. 과도한 요청 제한도 이용자별로 구분하지 않고 서버 전체 기준으로 적용합니다.

검색어는 결과를 찾기 위해 조회 서버를 거쳐 VLR.GG 검색 페이지 조회에 사용됩니다. 이때 VLR.GG에는 조회 서버가 요청을 보내며, 이용자의 IP 주소나 기기 정보는 전달하지 않습니다.

### 처리의 법적 근거

위 정보는 이용자에게 별도 동의를 받지 않고 자동으로 처리됩니다. 동의 없이 처리하는 범주별 근거는 다음과 같습니다(「개인정보 보호법」 제22조 제3항).

| 구분 | 처리 근거 |
| --- | --- |
| 오류 보고 | 「개인정보 보호법」 제15조 제1항 제4호(정보주체와 체결한 계약의 이행). 정상적으로 작동하는 앱을 제공하려면 비정상 종료·응답 없음의 원인을 찾아 고쳐야 합니다. |
| 앱 사용 세션 측정 | 「개인정보 보호법」 제15조 제1항 제4호. 오류가 어느 세션에서 났는지 연결하고 오류 없이 사용된 비율을 확인해야 오류 수정의 우선순위와 수정 결과를 판단할 수 있습니다. |
| 조회 서버 접속 기록 | 「개인정보 보호법」 제15조 제1항 제4호. 이용자가 요청한 경기·팀·선수·뉴스·검색 정보를 제공하고, 장애가 나면 원인을 확인해 복구하는 데 필요합니다. |

앱에는 회원가입이나 별도 약관이 없지만, 개발자는 이용자가 앱을 설치해 정보를 요청하고 개발자가 이를 제공하는 이용 관계를 위 근거의 계약으로 봅니다. 세 범주 모두 이름·연락처·계정 같은 신원 정보를 담지 않으며, 개발자는 이 정보를 위 목적에만 쓰고 특정 이용자를 찾아내는 데 쓰지 않습니다.

### 기기에만 저장하는 정보

즐겨찾기한 팀·선수 정보(식별 번호, 이름, 태그, 국가, 이미지 주소)는 이용자의 기기 안에만 저장하며 개발자의 서버로 전송하지 않습니다.

다만 운영체제의 백업 기능을 켠 경우 이 파일이 백업에 포함될 수 있습니다.

- Android: 앱은 Android 자동 백업을 허용합니다. 기기에서 백업을 켜 두었다면 앱 데이터가 이용자의 Google 계정 Google Drive 비공개 영역에 백업될 수 있습니다.
- iOS: 즐겨찾기 파일은 기본적으로 iCloud 또는 컴퓨터 백업 대상인 위치에 저장됩니다.

이 백업은 이용자 계정의 운영체제 기능으로 이루어지며, 개발자는 백업 데이터를 열람할 수 없습니다.

### 이미지 표시

팀 로고, 선수 사진 같은 이미지는 기기가 VLR.GG가 게시한 이미지 주소(예: `www.vlr.gg`, `owcdn.net`)에서 직접 불러옵니다. 이 과정에서 해당 사이트는 일반적인 인터넷 통신과 마찬가지로 기기의 IP 주소 등을 받을 수 있으며, 그 처리에는 해당 사이트의 정책이 적용됩니다.

### 처리하지 않는 정보

- 위치 정보, 연락처, 사진·파일, 카메라·마이크
- 광고 식별자, 광고·마케팅 목적의 이용 행태 분석(Firebase Analytics 등)
- 오류 보고·세션 데이터에 연결되는 사용자 ID나 이용자가 입력한 정보

Android 앱이 요청하는 권한은 인터넷 접속과 네트워크 연결 상태 확인뿐입니다. 네트워크 연결 상태 확인 권한은 Firebase 라이브러리가 오류 보고·세션 데이터 전송을 위해 추가합니다. iOS 앱은 별도 권한을 요청하지 않습니다.

## 2. 보유·이용 기간과 파기

| 항목 | 보유 기간 |
| --- | --- |
| 오류 보고 | Firebase Crashlytics가 오류 기록과 관련 식별자를 90일 동안 보관한 뒤 삭제를 시작합니다. |
| 앱 사용 세션 측정 | Firebase는 세션 식별자를 Crashlytics가 수집하는 정보로 안내하지만, 오류 없이 끝난 세션 기록의 보유 기간은 따로 공개하지 않습니다. 이 기록은 Firebase 설치 식별자에 연결돼 있어 아래 "Firebase 설치 식별자" 기준에 따라 삭제됩니다. |
| Firebase 설치 식별자 | Firebase가 개발자의 삭제 요청 전까지 보관합니다. 개발자가 삭제를 요청하면 180일 이내에 이 식별자와 여기에 연결된 오류 보고·세션 데이터가 Firebase 설치 식별자를 사용하는 모든 Firebase 서비스의 운영·백업 시스템에서 삭제됩니다. |
| 조회 서버 접속 기록 | 서버 프로그램의 운영 기록과 함께 Google Cloud 서울 리전의 로그 저장소에 30일 동안 보관한 뒤 자동으로 삭제됩니다. |
| 기기에 저장한 즐겨찾기 | 이용자가 즐겨찾기를 해제하거나 앱(또는 앱 데이터)을 삭제할 때까지 |

보유 기간이 지난 정보는 각 서비스의 자동 삭제 기능으로 파기합니다. 앱 서비스를 종료하면 개발자는 Firebase 설치 식별자 삭제나 Firebase 프로젝트 삭제로 남은 오류 보고·세션 데이터를 파기합니다. 개발자는 접속 기록을 다른 저장소로 내보내지 않으며, 장애 분석을 위해 일부를 내려받은 경우에는 분석을 마친 뒤 지체 없이 삭제합니다.

## 3. 개인정보의 제3자 제공

개발자는 이용자의 개인정보를 제3자에게 제공하지 않습니다. 법령에 따라 제공 의무가 생기는 경우에는 그 법령에 따릅니다.

## 4. 개인정보 처리의 위탁

개발자는 앱 운영을 위해 다음과 같이 개인정보 처리 업무를 위탁합니다.

| 수탁자 | 위탁 업무 |
| --- | --- |
| Google Asia Pacific Pte. Ltd. (Firebase Crashlytics) | 앱 오류 보고와 세션 데이터의 수집·저장·분석 |
| Google Cloud Korea LLC (Google Cloud: Cloud Run, Cloud Logging) | 조회 서버 운영과 접속 기록 저장 |

수탁자는 각 서비스 약관상 개발자와 계약을 맺는 회사입니다. Firebase Crashlytics는 개발자의 거주 지역(아시아·태평양)에 따라 Google Asia Pacific Pte. Ltd.가 계약 당사자입니다. Google Cloud는 결제 계정 주소에 따라 계약 당사자가 정해지며, 대한민국 결제 계정(원화 결제)은 Google Cloud Korea LLC가 재판매자로서 계약 당사자입니다. 실제 처리는 Google LLC와 Firebase, Inc. 등 Google 계열사가 맡으며, 처리 업무의 일부는 재수탁자 목록([Firebase](https://firebase.google.com/terms/subprocessors), [Google Cloud](https://cloud.google.com/terms/subprocessors))에 기재된 회사에 다시 맡겨질 수 있습니다.

## 5. 개인정보의 국외 이전

### Firebase Crashlytics

Firebase Crashlytics는 Google의 전 세계 인프라에서 동작하며, Google은 Firebase 데이터를 Google 또는 그 재수탁자가 시설을 운영하는 어느 국가에서나 처리할 수 있다고 밝히고 있습니다. 따라서 오류 보고와 세션 데이터는 국외로 이전됩니다.

| 항목 | 내용 |
| --- | --- |
| 이전받는 자 | Google Asia Pacific Pte. Ltd.(계약 당사자), 실제 처리를 맡는 Google LLC·Firebase, Inc. 등 Google 계열사, 4항의 재수탁자 목록에 기재된 회사 |
| 이전받는 자의 연락처 | Google Asia Pacific Pte. Ltd.: 8 Marina View, Asia Square 1 #30-01, Singapore 018960<br>Google LLC: 1600 Amphitheatre Parkway, Mountain View, CA 94043, USA<br>개인정보 문의(Firebase, Inc.와 재수탁자 포함): [Firebase 개인정보 보호 문의](https://firebase.google.com/support/privacy/dpo) |
| 이전되는 국가 | Google 데이터센터가 있는 국가: 미국, 칠레, 우루과이, 아일랜드, 네덜란드, 덴마크, 핀란드, 벨기에, 독일, 영국, 대만, 싱가포르, 일본(2026년 10월 17일 기준 [Google 데이터센터 위치](https://www.google.com/about/datacenters/locations/)). Firebase 데이터 처리·보안 약관은 Google 또는 재수탁자가 시설을 운영하는 국가에서 처리할 수 있다고 정하고 있어, 실제 처리 국가는 이 중 일부이거나 Google·재수탁자가 시설을 운영하는 다른 국가일 수 있습니다. |
| 이전 근거 | 「개인정보 보호법」 제28조의8 제1항 제3호 가목(이용자와의 계약 이행에 필요한 처리위탁·보관으로, 같은 조 제2항의 사항을 이 처리방침에 공개) |
| 이전 항목 | 1항의 "오류 보고"와 "앱 사용 세션 측정" 항목 |
| 이전 시기와 방법 | 오류 보고: 정식 버전에서 비정상 종료·응답 없음이 발생한 뒤 앱이 인터넷으로 전송<br>세션 데이터: 정식 버전에서 앱을 실행하거나 일정 시간이 지난 뒤 다시 화면 앞으로 가져올 때 앱이 인터넷으로 전송 |
| 이전 목적 | 오류 원인 파악과 수정, 앱 안정성 지표 산출 |
| 보유·이용 기간 | 오류 보고: 90일 후 삭제 시작<br>세션 데이터·Firebase 설치 식별자: 2항의 "앱 사용 세션 측정"·"Firebase 설치 식별자" 기준에 따름 |
| 거부 방법과 효과 | 현재 앱 안에는 오류 보고·세션 데이터 전송을 끄는 설정이 없습니다. 전송을 원하지 않으면 앱을 이용하지 않거나 삭제할 수 있으며, 이 경우 앱을 이용할 수 없습니다. |

### 조회 서버(Google Cloud)

조회 서버(Cloud Run)와, 접속 기록·서버 프로그램의 운영 기록을 저장하는 로그 저장소(Cloud Logging)는 모두 Google Cloud 서울 리전(`asia-northeast3`)에 있으므로 이 기록은 국외로 이전하지 않습니다.

다만 2026년 10월 17일 서울 저장 전환이 끝나기 전에 기록된 접속 기록과 운영 기록은 국외 데이터센터에 저장될 수 있는 `global` 위치의 로그 저장소에 남아 있습니다. 이 기록은 30일 보존 기간에 따라 자동으로 삭제되며, 2026년 11월 16일 무렵 모두 삭제될 예정입니다. 전환 뒤에도 `global` 저장소에 남는 Cloud Run 시스템 기록(인스턴스 시작·종료, 메모리 부족 등)에는 IP 주소·User-Agent·요청 주소나 요청 추적 번호가 없습니다.

## 6. 정보주체의 권리와 행사 방법

이용자는 개발자에게 언제든지 개인정보의 열람, 정정·삭제, 처리정지를 요구하고 동의를 철회할 수 있습니다.

- 요청은 11항의 문의처로 보낼 수 있습니다. 개발자는 지체 없이 확인하고 결과를 알립니다.
- 앱에는 계정이 없어 개발자가 특정 이용자의 오류 보고·세션 데이터나 접속 기록을 찾지 못할 수 있습니다. 이 경우 그 사유를 알립니다.
- 기기에 저장한 즐겨찾기는 앱에서 직접 해제하거나 앱 데이터를 지워 삭제할 수 있습니다.
- 법정대리인이나 위임을 받은 사람을 통해서도 권리를 행사할 수 있습니다.

## 7. 안전성 확보 조치

- 앱 정식 버전과 조회 서버는 HTTPS로 통신합니다.
- 서버 프로그램은 요청에서 나온 IP 주소·검색어 같은 값을 운영 로그에 쓰지 않고, 오류 기록에는 정해진 범위의 정보만 남깁니다.
- Firebase 설정과 배포 자격 증명은 공개 저장소에 두지 않고 보호된 환경에서만 사용합니다.
- 클라우드 운영 자원에 대한 접근 권한을 필요한 범위로 제한합니다.

## 8. 쿠키 등 자동 수집 장치

앱은 쿠키나 웹 추적 장치를 사용하지 않습니다. 다만 1항에서 설명한 것처럼 Firebase Crashlytics가 오류 보고와 세션 측정을 위해 앱 설치 단위의 식별자(Crashlytics Installation UUID, Firebase installation ID)와 세션 식별자를 생성해 사용합니다.

## 9. 만 14세 미만 아동의 개인정보

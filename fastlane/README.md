# Internal app deployment process

The two app workflows are manual-only and deploy the immutable `main` commit that triggered the run. They require `APP_VERSION` (one to three numeric components) and a positive `APP_BUILD_NUMBER`; Android requires a successful `verify` job in the latest `main` push `ci.yml` run and attempt for that exact commit, without waiting for the `ios` job. Missing evidence or a run/attempt change during lookup stops deployment. iOS deployment still requires the entire matching CI run to succeed.

Android builds use `FIREBASE_ANDROID_CONFIG_BASE64` through `scripts/firebase/with_config.py android -- bundle exec fastlane android internal`. The wrapper removes its private temporary configuration on success, failure, and handled termination; actual configuration builds disable Gradle build/configuration caches. See [Crashlytics setup](../docs/app-crashlytics.md).

iOS builds use `FIREBASE_IOS_CONFIG_BASE64` through `scripts/firebase/with_config.py ios -- bundle exec fastlane ios internal`. Xcode copies the configuration into the app bundle and uploads dSYMs synchronously for collection-enabled builds. The wrapper removes the injected input; lane cleanup removes the archive and derived data.

Android needs an enrolled Play developer account, an existing app record for `kr.co.cotton.vlrgg_mobile`, a compatible upload key, internal testers, and these environment secrets: `API_BASE_URL`, `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`. Set the environment variables `ANDROID_PLAY_WIF_PROVIDER` and `ANDROID_PLAY_SERVICE_ACCOUNT` for WIF with service-account impersonation. Fastlane uses the auth action’s temporary Application Default Credentials; no long-lived service-account JSON key is needed. The service account must be limited to the existing app and testing releases; the workflow materializes the keystore only in runner temporary storage and removes it and the signed bundle on success or failure.

iOS needs Apple Developer Program and App Store Connect enrollment, an existing app record for `kr.co.cotton.vlrggmobile`, a compatible distribution certificate/profile, internal testers, and these environment secrets: `API_BASE_URL`, `IOS_TEAM_ID`, `IOS_CERTIFICATE_BASE64`, `IOS_CERTIFICATE_PASSWORD`, `IOS_PROVISION_PROFILE_BASE64`, `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, and `APP_STORE_CONNECT_KEY_CONTENT_BASE64`. The lane derives the profile UUID, refuses to overwrite an existing installed profile, and creates only a temporary keychain/profile/configuration. Fastlane 2.239.0 uses an owned temporary API-key directory with pinned Xcode 26.6; cleanup never removes credentials from the user's home key directory.

Run only from the Actions page on `main`; the lanes reject any other invocation and require the checkout HEAD, workflow SHA, and frozen source SHA to match. A rerun preserves the original source SHA and input version. Workflow concurrency serializes only these repository workflows, not local or store-console uploads. Both lanes query the target store before upload and refuse reported reused build numbers, but those queries expose only limited published states: a missing result is not proof that an uncertain upload failed. If an upload response is lost or processing is incomplete, explicitly verify the Play Console bundle/track receipt or App Store Connect TestFlight build status before starting a fresh workflow; a lookup error fails closed.
